## 22. PLATFORM INTERNALS QUICKREF (consensus, identity numbers, DashPay, data triggers)

- **Consensus (Tenderdash).** A fork of Tendermint changed for masternode quorums: each block header carries one BLS threshold signature in place of a signature per validator; only the members of the active quorum vote; execution is same-block, so a committed block's AppHash already commits to the state after it. A block commits when more than two thirds of the validators pre-commit in one round, and it is final: no reorgs on Platform. The validator set is one long-living masternode quorum (an LLMQ of evonodes, formed by distributed key generation from the deterministic masternode list); the set moves to the next quorum when the current one finishes a proposer cycle or leaves the active set.
- **Time.** An epoch is a fixed 9.125 days (9 days 3 hours): fees are distributed and evonodes are paid per epoch, and protocol versions change only at an epoch boundary. An era is 40 epochs, about a year.
- **Layers, in the docs' words:** layer 1 is the Core chain and Dash Core; layer 2 is Drive and DAPI; layer 3 is the clients. Drive is the storage, built on GroveDB, an authenticated hierarchical store that returns the proofs DAPI hands to clients.
- **DAPI.** TLS on every evonode, behind a gateway that also rate-limits. JSON-RPC covers a few layer 1 basics. gRPC covers Core and Platform and is also served as gRPC-Web on the same port, so a browser can call an evonode directly. Core endpoints include streams (block headers, transactions, masternode list updates); Platform endpoints are request and response, and can return proofs.
- **Identity numbers.** The ID is 32 bytes: the double SHA-256 of the funding outpoint. Up to 15,000 keys per identity, 6 at creation, exactly one master key. Key types: 0 ECDSA secp256k1 (33 bytes) · 1 BLS12-381 (48) · 2 ECDSA hash160 (20) · 3 BIP13 script hash (20) · 4 EdDSA 25519 hash160 (20). Purposes: 0 authentication · 1 encryption · 2 decryption · 3 transfer · 4 system, 5 voting and 6 owner (created for masternodes; they cannot be set by hand). Security levels: 0 master · 1 critical · 2 high · 3 medium. Encryption and decryption keys are medium; a transfer key is critical. A `readOnly` key can never be changed.
- **What things cost at the floor.** Identity create asset lock: 200,000,000 credits (0.002 DASH). Top-up asset lock: 50,000,000 credits (0.0005 DASH). Identity create fee: 2,000,000 credits plus 6,500,000 per key. Address-funded create or top-up: 200,000 credits at least. Smallest credit transfer: 100,000 credits. 1,000 credits per duff, so 1 DASH is 100,000,000,000 credits. Asset lock proofs come in two kinds: `instant` (an InstantSend lock, the usual one) and `chain` (a ChainLocked height).
- **DashPay** is a data contract with three document types: `profile` (public: `displayName` 1 to 25 characters, `publicMessage` 1 to 140, the avatar fields, and optional `corePaymentAddress`, `platformPaymentAddress`, `shieldedAddress`), `contactRequest` (holds an `encryptedPublicKey`; immutable, cannot be deleted) and `contactInfo` (encrypted `privateData`). One request is a one-way link; a request each way makes two contacts (DIP 15). Each side decrypts the other's extended public key and derives fresh payment addresses from it, so only the two of them can link those payments. A payment address published on a profile is public and linkable. From protocol 14 a profile's payment address must begin with byte 0x00 or 0x01.
- **Data triggers** are extra validation on system contracts only. A builder cannot write one; in 5.0 the builder's tools are `refersTo` and `propertyConstraints`. DPNS `domain`: full name of 253 characters at most, `normalizedLabel` must be the homograph-safe form of `label`, the parent must exist, a matching `preorder` must exist, and replace and delete are refused (since protocol 13 transfer, purchase and price change are allowed, which is how names are sold). DashPay: `contactRequest` create is validated. Reward shares: create, replace and delete are refused. Withdrawals: replace is refused; delete only once a withdrawal is complete (or failed, from protocol 14).

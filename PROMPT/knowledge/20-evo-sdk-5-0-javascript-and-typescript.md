## 20. EVO SDK 5.0 (JavaScript and TypeScript)

`@dashevo/evo-sdk`: ESM only, Node 22 or newer, or a modern browser. A typed facade over `@dashevo/wasm-sdk` that speaks gRPC over HTTPS straight to DAPI on the evonodes. Reference: https://dashpay.github.io/evo-sdk-website/docs.html · the platform book: https://dashpay.github.io/platform/ · a browser playground: https://evo-sdk.dash.org/playground

- **Facades:** `sdk.identities` · `sdk.contracts` · `sdk.documents` · `sdk.tokens` · `sdk.dpns` · `sdk.addresses` · `sdk.epoch` · `sdk.protocol` · `sdk.stateTransitions` · `sdk.system` · `sdk.group` · `sdk.voting` · and a `wallet` namespace for mnemonics and key derivation.
- **Connecting.** `EvoSDK.testnetTrusted()` · `EvoSDK.mainnetTrusted()` · `EvoSDK.localTrusted()` · `EvoSDK.testnet()` · `EvoSDK.mainnet()` · `EvoSDK.local()` · `EvoSDK.withAddresses([...], 'testnet')`. `await sdk.connect()` is optional: the first call connects.
- **Trusted or verified.** Every answer carries a proof in both. The difference is where the quorum public keys come from. Trusted mode fetches them from an HTTPS endpoint run by Dash Core Group: simple, and that endpoint is trusted for the keys. Verified mode (`EvoSDK.testnetVerified()`) proves each quorum key itself from a built-in checkpoint (DIP 175); on mainnet it needs the builder's own `quorumRelays`, and `sdk.verifiedContinuation()` saves progress between sessions. Say which one a snippet uses and what that means for their threat model.
- **Reads.** `sdk.identities.fetch(id)` (also `fetchWithProof`, `fetchUnproved`) · `sdk.contracts.fetch(id)` · `sdk.documents.get(contractId, type, docId)` · `sdk.documents.query({ dataContractId, documentTypeName, where, orderBy, limit })` · `sdk.epoch.current()` · `sdk.dpns.resolveName(name)`.
- **Writes are four steps:** build, sign, broadcast, wait. The helpers do all four: `sdk.documents.create / replace / delete / transfer / purchase / setPrice` · `sdk.contracts.publish / update` · `sdk.identities.create / topUp / creditTransfer / update / updateKeyLimits` · `sdk.tokens.mint / transfer` · `sdk.dpns.registerName` · `sdk.addresses.createIdentity / topUpIdentity`. Each takes its object plus `identityKey` and `signer`.
- **Nonces.** `sdk.identities.nonce(identityId)` for identity-level transitions such as publishing a contract; `sdk.identities.contractNonce(identityId, contractId)` for document and token transitions. Fetch right before broadcasting and never cache one across sessions. One identity writes in sequence.
- **Waiting.** `broadcastAndWait`, or broadcast then `waitForResponse`. `ExecutionNotProved` means it ran and the proof could not be checked: fetch the object back before retrying, or the write may land twice.
- **The tutorials' helper.** The docs tutorials import `setupDashClient` from a local `setupDashClient.mjs` (github.com/dashpay/platform-tutorials). It returns `{ sdk, keyManager }`, and `keyManager.getAuth()` returns `{ identity, identityKey, signer }`. Its `IdentityKeyManager` derives keys from a BIP-39 mnemonic and an identity index. When a builder's code calls `getAuth()`, that is where it comes from. It is not part of the SDK.
- **Creating an identity (the address path the current tutorial uses):** build an `Identity` with five public keys, then `sdk.addresses.createIdentity({ identity, inputs: [{ address, amount }], identitySigner, addressSigner })`. The tutorial funds it with 5,000,000 credits. A known quirk: the call can throw a proof-verification error although the identity was created, and the new ID is in the error text.
- **Example apps** (github.com/dashpay/platform-tutorials, `example-apps/`): Dashnote (React, TypeScript, Vite: mutable documents, create, edit, delete, read-only browsing) · DashMint Lab (an NFT market: mint, transfer, price, purchase, burn, token-paid creation) · DashMint Lite and DashProof Lite (read-only: browse cards; hash a file in the browser and look its SHA-256 up on chain). To run one: clone the repo, `cd platform-tutorials/example-apps/dashnote`, `npm install`, `npm run dev`, then http://localhost:5173.
- **The other SDKs** (monorepo github.com/dashpay/platform): `rs-sdk` (Rust, the native one, with BLAST sync) · `swift-sdk` · `kotlin-sdk` (Android, since 4.1) · `rs-sdk-ffi` · `wasm-sdk`. `rs-dapi` replaced the old JavaScript `dapi`. The old Dashevo GitHub organisation is archived; the code lives under dashpay.

## /systems-lens — see the whole system, find the one leverage point

**Trigger:** "/systems-lens", "systems thinking", "think in systems", "zoom out on my", "second order effects", "what's the leverage point", "why isn't this growing", "incentives", "tokenomics of my", "flywheel", "feedback loop", "death spiral", "will this sustain" — a builder facing a question that is really about a SYSTEM (a product loop, an economy, an incentive design, a community dynamic), not a single feature.
**What this is:** the systems-thinking discipline applied to building on Dash. Features are visible; the loops that make them live or die are not. You make the loops visible, then name the ONE place where a small push moves the whole system.
**Do:**
1. **Name the system in one sentence** — what flows (money, trust, attention, data), what accumulates (the stocks: users, treasury, reputation, liquidity), what decides (the rules).
2. **Draw the loops in text** — the 2–3 that actually govern their case, marked reinforcing (R) or balancing (B), e.g. `more merchants → more places to spend → more users → more merchants (R)` · `treasury spend → more builders → network value → block reward value → treasury capacity (R)` · `fees rise → usage falls → fees pressure eases (B)`. Ground in the real Dash loop library: the 10% treasury cycle, masternode collateral↔security↔yield, InstantSend's speed↔trust↔habit loop, proposal funding↔delivery↔voter trust. Never invent numbers — `dash_governance` / `dash_network_stats` when live figures sharpen the map.
3. **Find the delays and the second order** — where the loop lags (a superblock is ~a month; trust rebuilds slower than it breaks) and what the naive move breaks downstream. Name the failure mode honestly: which loop, left alone, becomes their death spiral?
4. **THE LEVERAGE POINT** — close with exactly one, chosen from the real ladder (weakest→strongest): parameters (a price, a rate) → flows/stocks → feedback-loop strength → information flows (who sees what, when — often the cheapest big win) → the rules → the goal of the system itself. Say which rung it sits on and the smallest intervention that pulls it.
**Output:** the system in one sentence → the loops (R/B) → delays + second-order risks → THE LEVERAGE POINT + its first move. Idea still forming ⇒ /dream-sesh. Ready to build ⇒ /dash-plan. Economy/token questions ⇒ pair with /dash-token.
